# Памятка: автономные боты на GitHub Actions (2026)

> Для меня-чайника и для нейросетей, которые будут это делать.
> Написана 25.11.2026 по опыту бота «Отключения Кумертау».
> Проверенные факты помечены ✅, опасные места — ⚠️.

---

## 0. Если читает ИИ-агент — прочти это первым

1. **Не верь `schedule` (cron) GitHub.** В 2026 году у новых репозиториев он
   часто не запускается вообще. Проверяй фактами: `gh run list --json event`
   ищи `schedule`. Если за 30–60 минут нет ни одного — считай, что cron мёртв.
2. **Не предлагай cron-job.org сразу.** Сначала попробуй «цепочку» (раздел 2):
   она не требует сторонних аккаунтов и токенов.
3. **Не запускай `gh api` без перенаправления вывода**, если команда может
   напечатать токены/секреты.
4. **Не храни токены в файлах репозитория.** Только GitHub Secrets.
5. **Не меняй секреты и конфиг без явного «да» пользователя.**
6. **Проверяй результат запуском**, а не по README: смотри логи Actions,
   `state.json`, реальные сообщения.
7. **Логи запуска доступны только после его завершения.** Для отладки делай
   короткий ручной запуск, а не жди 5 часов.
8. Пользователь — новичок: пиши простыми словами, давай точные пути и команды.

## 1. Главная проблема 2026 года: cron GitHub не работает

**Симптом:** workflow активен, файл правильный, `workflow_dispatch` работает,
а запусков с `event=schedule` нет ни одного — час, два, сутки.

**Причина:** массовый сбой/деградация планировщика GitHub в 2026-м (десятки
обсуждений в community: #201738, #212519, #212721, #213230, #213381).
Официально `schedule` и раньше был «best effort» с задержками до 20–30 минут,
но сейчас у новых репозиториев он может не стартовать вообще.

**Как проверить за 2 минуты:**

```powershell
gh run list -R ВЛАДЕЛЕЦ/РЕПО --limit 20 --json createdAt,event |
  ConvertFrom-Json | Where-Object { $_.event -eq "schedule" }
```

Пусто → cron не работает.

**Что НЕ помогает (проверено):**
- переключить `gh workflow disable/enable`;
- переписать cron на другую минуту;
- коммит «для активности»;
- ждать «первый запуск иногда задерживается» (актуально для старых репозиториев,
  не для новых в 2026).

**Что помогает:** цепочка (раздел 2) — внешний аккаунт не нужен.

## 2. Рабочее решение: самоподдерживающаяся цепочка

### Идея

Один запуск workflow работает ~5 часов: каждую минуту опрашивает Telegram,
каждую минуту проверяет источник. В конце **сам запускает следующий такой же
запуск**. И так круглосуточно. Никаких cron и сторонних сервисов.

### Почему это законно и работает

- ✅ Проверено 25.11.2026: workflow может запустить сам себя **штатным**
  `GITHUB_TOKEN`, если в workflow есть `permissions: actions: write`.
  Ответ API — `204`. Новый запуск реально появляется.
- Ограничение GitHub: события, созданные `GITHUB_TOKEN`, не запускают новые
  workflow — **кроме** `workflow_dispatch` и `repository_dispatch`.
- Публичный репозиторий = бесплатные минуты Actions (стандартные раннеры).
- Лимит одного job — 6 часов. Поэтому цикл 5 часов, а передача эстафеты —
  отдельным коротким job.

### Схема

```
[ручной запуск] → loop (5 часов) → relay (10 секунд) → loop (5 часов) → ...
```

### Готовый шаблон `.github/workflows/bot-chain.yml`

```yaml
name: Bot chain

on:
  workflow_dispatch:

permissions:
  contents: write     # коммитить state.json
  actions: write      # запускать следующий запуск

concurrency:
  group: bot-chain
  cancel-in-progress: false   # НЕ убивать текущую цепочку

jobs:
  loop:
    runs-on: ubuntu-latest
    timeout-minutes: 330      # 5,5 часа; больше 360 нельзя
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0      # нужно для git pull --rebase
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - name: Работа
        env:
          TOKEN: ${{ secrets.TOKEN }}
        run: |
          set -u
          git config user.name "bot"
          git config user.email "bot@users.noreply.github.com"
          for i in $(seq 1 300); do          # 300 минут = 5 часов
            python bot.py --tick || echo "ошибка — продолжаю"
            if [ -n "$(git status --porcelain state.json)" ]; then
              git add state.json
              git commit -q -m "state: $(date -u +%Y-%m-%dT%H:%MZ)" || true
              for a in 1 2 3; do
                if git pull --rebase --autostash -q origin main && git push -q origin main; then
                  break
                fi
                sleep 5
              done
            fi
            [ "$i" -lt 300 ] && sleep 60
          done

  relay:
    needs: loop
    if: always()                # сработает, даже если loop упал/умер по таймауту
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - name: Передать эстафету
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          for a in 1 2 3 4 5; do
            code=$(curl -s -o /dev/null -w '%{http_code}' -X POST \
              -H "Authorization: Bearer $GH_TOKEN" \
              -H "Accept: application/vnd.github+json" \
              -H "Content-Type: application/json" \
              -d '{"ref":"main"}' \
              "https://api.github.com/repos/$GITHUB_REPOSITORY/actions/workflows/bot-chain.yml/dispatches")
            echo "попытка $a -> HTTP $code"
            [ "$code" = "204" ] && exit 0
            [ "$code" = "404" ] && exit 0    # workflow отключён — останавливаемся тихо
            sleep 30
          done
          echo "ЭСТАФЕТА НЕ ПЕРЕДАНА" >&2
          exit 1
```

### Запуск один раз

```powershell
gh workflow run bot-chain.yml -R ВЛАДЕЛЕЦ/РЕПО
```

Дальше проверять раз в сутки:

```powershell
gh run list -R ВЛАДЕЛЕЦ/РЕПО --workflow bot-chain.yml --limit 5
```

Должны появляться новые запуски примерно каждые 5 часов.

### Как остановить

1. Actions → нужный workflow → **Disable workflow**.
2. Текущий запуск → **Cancel workflow** (иначе доработает до 5 часов).
3. Relay получит `404` и тихо завершится — это нормально.

## 3. Чек-лист нового бота (по шагам)

1. **Источник данных.** Найди публичный endpoint без токена (виджет, RSS, HTML).
   Проверь `curl.exe` с ПК. Если с ПК недоступен (например, Telegram) — проверь
   с раннера GitHub (workflow `curl`).
2. **Репозиторий.** Публичный (бесплатные минуты). Имя латиницей.
3. **Скрипт** (Python, только стандартная библиотека):
   - `--dry-run` — ничего не отправлять и не сохранять;
   - `--verbose` — печатать разбор;
   - `state.json` — `max_id`/`offset` + список отправленного;
   - первый запуск = запомнить состояние, не спамить старым;
   - защита: нет токена/chat_id → **не трогать state** и выйти с ошибкой.
4. **Секреты** — только через `gh secret set` (или UI). В коде их нет.
5. **Первый тест** — `workflow_dispatch` + `--dry-run`, смотри лог.
6. **Боевой запуск** — проверь реальное сообщение у пользователя.
7. **Цепочка** — добавь `bot-chain.yml`, запусти вручную, проверь через 5 часов,
   что эстафета передалась.
8. **Документация** — `README.md` + `ИНСТРУКЦИЯ.md` для человека.

## 4. Грабли, за которые уже заплачено временем

### 4.1. Состояние коммитится каждый запуск → сотни коммитов
Причина: в `state.json` писался `last_run` (время), оно меняется всегда.
**Лечится:** хранить только то, что реально меняется (`max_id`, `sent`,
`tg_offset`). Тогда коммит — только при новостях.

### 4.2. Конфликт при коммите состояния
Два запуска (cron + цепочка) или ручной коммит → `git push` отклонён.
**Лечится:** перед push `git pull --rebase --autostash origin main`,
и `fetch-depth: 0` в checkout. Повторить 2–3 раза.

### 4.3. Повторная отправка после сбоя
Если процесс упал, `max_id` мог не сохраниться → старые записи уйдут снова.
**Лечится:** список `sent` (id отправленного) и проверка «уже отправлялась».

### 4.4. Гонка двух процессов
Цепочка и cron одновременно прочитали state → оба отправили.
**Лечится:** `concurrency` + список `sent` + редкие запуски. Идеально — один
источник запуска.

### 4.5. `GITHUB_TOKEN` не запускает workflow
`git push` от `GITHUB_TOKEN` не триггерит workflow (защита от рекурсии).
`workflow_dispatch`/`repository_dispatch` — **триггерит** (проверено).
Если нужен другой тип события — нужен PAT, но для цепочки не требуется.

### 4.6. Логи недоступны, пока запуск идёт
`gh run view --log` → ошибка. **Лечится:** короткий ручной запуск для отладки;
либо `state.json` как индикатор (offset/меню/ids меняются → код работает).

### 4.7. PowerShell ломает команды
- `curl` — это алиас `Invoke-WebRequest`. Использовать **`curl.exe`**.
- Внутренние кавычки в `--jq '... "..."'` вырезаются → jq падает
  (`function not defined: completed/0`). **Лечится:** `--json` +
  `ConvertFrom-Json`, либо экранировать.
- Кириллица в консоли: `[Console]::OutputEncoding = [Text.Encoding]::UTF8`,
  `$env:PYTHONUTF8="1"`, для `.bat` — `chcp 65001`.
- Python-код с кириллицей через stdin может искажаться — запускать из файла.

### 4.8. Кириллица в `.bat`/`.cmd`
Командная строка Windows ломает кириллицу. В `.bat` — только ASCII,
либо `chcp 65001` + файл в UTF-8 (проверять).

### 4.9. Telegram недоступен с ПК
`api.telegram.org` может быть заблокирован провайдером. Отправка и опрос —
только с раннера GitHub. Локально тестировать чистые функции (selftest).

### 4.10. Бот не может написать первым
Пока человек не нажал Start, Telegram не даёт боту писать. `getUpdates`
покажет `CHATS: []`, пока нет нажатия. Chat id берётся из `getUpdates`
(на раннере!) и кладётся в секрет.

### 4.11. Виджет ВК отдаёт только 10 последних записей
Опрос раз в минуту достаточен (13 записей за 2 дня), но при 10+ новых
записей за интервал часть потеряется — скрипт должен предупреждать в логе.

### 4.12. Не отключать чужие программы
Правило пользователя (16.11.2026): никакой скрипт/ярлык не закрывает чужие
программы «заодно». Закрытие — отдельным ярлыком.

## 5. Диагностика: что смотреть, когда «не работает»

```powershell
# 1. Идут ли запуски вообще
gh run list -R ВЛАДЕЛЕЦ/РЕПО --limit 10

# 2. Есть ли плановые (cron)
gh run list -R ВЛАДЕЛЕЦ/РЕПО --limit 30 --json event |
  ConvertFrom-Json | Where-Object { $_.event -eq "schedule" }

# 3. Что в последнем запуске (только после завершения!)
gh run view ID -R ВЛАДЕЛЕЦ/РЕПО --log |
  Select-String -Pattern "ОШИБКА|Отправлено|Новых|HTTP"

# 4. Состояние в репозитории
gh api repos/ВЛАДЕЛЕЦ/РЕПО/contents/state.json --jq .content |
  ForEach-Object { [Text.Encoding]::UTF8.GetString([Convert]::FromBase64String($_)) }

# 5. Секреты (только имена и даты, значения не показываются)
gh secret list -R ВЛАДЕЛЕЦ/РЕПО

# 6. Статус GitHub Actions
curl.exe -s https://www.githubstatus.com/api/v2/status.json
```

Типичные коды при самозапуске:
- `204` — успех;
- `401` — токен неверный;
- `403` — нет права `actions: write`;
- `404` — workflow отключён или файла нет на ветке `main`;
- `422` — нет ветки/триггера.

## 6. Безопасность

- Токены — только в **Secrets**; в логах GitHub они маскируются как `***`.
- Публичный репозиторий: любой видит код, но **не** секреты.
- Fine-grained PAT (если понадобится): только этот репозиторий, только нужное
  право (Actions: write), срок 1 год, хранить как секрет.
- Не отправлять в сторонние сервисы персональные данные и ключи.
- Если токен засветился — отозвать (`@BotFather /revoke`, GitHub → токены)
  и заменить секрет. Токен в чате = уже засветился.

## 7. Словарь для чайника

| Слово | Что это |
|---|---|
| workflow | файл-инструкция в `.github/workflows/*.yml` |
| job | один блок работы внутри workflow (максимум 6 часов) |
| run | один запуск workflow (виден в Actions) |
| `workflow_dispatch` | запуск вручную (кнопка Run workflow / `gh workflow run`) |
| `schedule` / cron | расписание GitHub (в 2026 ненадёжно) |
| secret | пароль/токен, спрятанный в настройках репозитория |
| `GITHUB_TOKEN` | временный токен раннера, живёт только запуск |
| state.json | память бота между запусками (коммитится в репозиторий) |
| relay | короткий job, который запускает следующий запуск цепочки |

## 8. Особенности этого проекта (как пример)

- Источник: `https://vk.com/widget_community.php?...gid=11784072&mode=4`
  (HTTP 200, cp1251, 10 записей, без токена).
- Telegram: отправка + `getUpdates` каждую минуту, offset в `state.json`.
- Меню: `ReplyKeyboardMarkup` + команды `/start`, `/news`, `/outages`,
  `/last`, `/status`; ответы только своему `chat_id`.
- Фильтр: `электроэнерг` + `тключен` (нормализация: нижний регистр, ё→е).
- Улица: `авиатор`, но не `Авиационная`.
- Цепочка: `.github/workflows/vk-loop.yml`.
- Запасной cron: `.github/workflows/vk-check.yml` (может ожить — не мешает).
- Тесты без сети: `python selftest.py`.
